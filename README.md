## Что в репозитории

Три ноутбука — по одному на каждую архитектуру из методички. В каждом
своя архитектура, свой датасет и свой тип данных, как и предполагает
презентация к занятию.

| № | Архитектура | Датасет | Тип данных | Тип задачи |
|---|---|---|---|---|
| 1 | Полносвязная сеть (FCN / MLP) | Palmer Penguins | табличные признаки | классификация на 3 класса |
| 2 | Свёрточная сеть (CNN) | MNIST | изображения 28×28 | классификация на 10 классов |
| 3 | Рекуррентная сеть (LSTM) | Airline Passengers | временной ряд | прогноз значения |

**Про обозначение FCN.** В задании полносвязная сеть названа FCN (fully connected network). В работе она реализована как MLP (multilayer perceptron) - это то же самое: сеть, в которой каждый нейрон слоя соединён со всеми нейронами предыдущего слоя. Отдельного смысла в различии букв нет, но чтобы не путать проверяющего, расхождение зафиксировано здесь явно.

Датасеты **не пересекаются** с практикой №1 (там были Abalone, Heart Disease,
Mushroom и Bike Sharing). MNIST выбран по рекомендации преподавателя.

## Как запустить

Ноутбуки рассчитаны на **Google Colab** — преподаватель рекомендовал работать
там, а в Colab уже установлены и PyTorch, и torchvision, и есть бесплатный GPU.

1. Открыть `.ipynb` в Colab: **Среда выполнения → Выполнить все**.
2. В ноутбуке 2 при первом запуске скачается MNIST (около 11 МБ) — это нормально.
3. В ноутбуке 3 скачается CSV-файл с рядом пассажиропотока.

Локально:

```bash
pip install -r requirements.txt
```

Ноутбуки выполнялись локально на CPU, и все графики в них настоящие, а не
прикреплённые картинки.

## Результаты

Метрики сняты с тестовой выборки, которая в обучении не участвовала.

| Работа | Метрики |
|---|---|
| MLP (пингвины) | Accuracy **0.9855**, Macro F1 **0.9829**, Weighted F1 0.9856. Ошибок 1 из 69 |
| CNN (MNIST) | Accuracy **0.9954** на тесте, 0.9936 на валидации, средняя точность по классам 0.9953. Ошибок 46 из 10 000 |
| LSTM (пассажиры) | MAE **29.4**, RMSE **32.4**, MAPP **6.31 %** |

### С чем сравнивали

Одна метрика сама по себе ничего не доказывает, поэтому в каждой работе есть
базовая линия — и сравнение с **сильнейшей** из них.

| Работа | Базовая линия | Модель | Выигрыш |
|---|---|---|---|
| MLP | самый частый класс — 0.4348 | 0.9855 | в **2.3 раза** лучше |
| MLP | равномерное угадывание — 0.2899 | 0.9855 | в 3.4 раза лучше |
| LSTM | наивный прогноз, MAE 45.8 | 29.4 | на 35.9 % меньше ошибки |
| LSTM | сезонно-наивный, MAE 49.5 | 29.4 | на 40.6 % меньше ошибки |

## Что общего у трёх работ

* **Ячейка 1 — зависимости, ячейка 2 — все импорты** с пояснением, зачем нужна
  каждая библиотека. Больше нигде импортов нет.
* Логика — в ячейках с кодом, все пояснения — в markdown. Каждый этап можно
  объяснить вслух.
* Порядок разделов соответствует методичке: **данные → архитектура →
  обучение → оценка**.
* **Очистка данных обязательна в каждой работе**, даже там, где датасет заведомо
  чистый: в CNN считаются дубликаты 70 000 картинок и пересечение между
  выборками, в LSTM проверяются регулярность ряда и выбросы.
* **EDA в каждой работе.** Для табличных данных — распределения и матрица
  корреляции. Для картинок матрица корреляции по 784 пикселям бессмысленна,
  поэтому считается корреляция между средними образами классов; для временного
  ряда вместо неё — автокорреляция, которая и показывает сезонность числом.
* В каждой работе есть честное сравнение с базовой линией. Одна метрика
  сама по себе ничего не доказывает.
* Обучающая, валидационная и тестовая выборки разделены отдельно, причём
  **«лучшая эпоха» выбирается по валидации, а не по тесту** — иначе оценка
  получается завышенной.
* Тестовая выборка используется ровно один раз, в самом конце, на уже готовых
  весах. Подбора гиперпараметров по тесту в работах нет.
* `random_state` / `manual_seed` зафиксированы, поэтому результаты
  воспроизводятся.
* В каждой работе есть раздел об **ограничениях** — что в данных или в методе
  мешает получить лучший результат.

Каждый ноутбук выполнен целиком с нуля, ошибок в ячейках нет. Метрики выше
